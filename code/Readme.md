# AI 안경 탐지 시스템

## 1. 프로젝트 개요

시험 응시자가 착용한 안경에 카메라가 장착되어 있는지 판별하는 AI 기반 시스템을 개발한다.

응시자의 정면 및 측면 사진을 입력받아 안경과 카메라 렌즈를 탐지하고, 두 사진의 분석 결과를 종합하여 AI 안경 착용 의심 여부를 판단한다.

최종적으로 실시간 카메라 촬영과 이미지 업로드를 모두 지원하는 GUI 프로그램을 구현하는 것을 목표로 한다.


## 2. 전체 시스템 구조

**사진 입력 → 탐지 → 분류 → 정면·측면 통합 판단 → 결과 출력**

1. **입력:** 동일한 응시자의 정면 사진 1장과 측면 사진 1장
2. **탐지(Detection):** YOLO11m으로 안경과 카메라 렌즈 탐지
3. **분류(Classification):** 일반 안경과 AI 안경 구분
4. **통합 판단(Decision):** 두 사진의 분석 결과를 결합하여 최종 판정
5. **결과 출력:** 판정 결과와 탐지 정보 표시

※ YOLO 단독 시나리오에서는 탐지와 분류가 하나의 모델에서 동시에 수행된다.

## 3. 데이터셋 구축 및 학습

### 3.1 데이터셋 구성

- 인터넷에서 수집한 일반 안경 및 카메라 장착 AI 안경 이미지 활용
- 정면, 측면, 45도 등 다양한 각도의 개별 이미지 사용
- 동일한 안경의 정면·측면 사진 쌍은 학습에 필수적이지 않음
- 현재 팀원들이 진행하는 바운딩 박스 라벨링 방식 유지
- 학습 및 검증 데이터의 중복 방지

### 3.2 실제 라벨링 클래스

현재 팀에서 사용 중인 `data.yaml` 기준:

| 클래스 번호 | 클래스 이름 | 설명 |
|---|---|---|
| 0 | `AIGlasses` | AI 안경 전체 |
| 1 | `AIGlasses_Lens` | AI 안경의 카메라 렌즈 |
| 2 | `NormalGlasses` | 일반 안경 전체 |

**라벨링 방식**

- 일반 안경: `NormalGlasses` 바운딩 박스
- AI 안경: `AIGlasses` 바운딩 박스
- 카메라 렌즈가 보이는 AI 안경: `AIGlasses`와 `AIGlasses_Lens` 바운딩 박스
- 카메라 렌즈가 보이지 않는 AI 안경: `AIGlasses` 바운딩 박스만 사용

### 3.3 현재 데이터셋 설정

```yaml
path: C:/Users/user/Desktop/labeldFiled
train: images/train
val: images/val

names:
  0: AIGlasses
```

※ `path`는 데이터셋을 구축한 컴퓨터의 로컬 경로이므로, 다른 컴퓨터에서 학습할 때는 실제 저장 위치에 맞게 변경해야 한다.

| 항목 | 설정 |
|---|---|
| 객체 탐지 모델 | YOLO11m |
| GPU | NVIDIA RTX 3060 12GB |

학습 설정은 초기값이며, 성능 평가 결과에 따라 변경할 수 있다.

## 4. 모델 구성 시나리오

**YOLO11m 사용은 확정이며, 분류 모델은 다음 후보 중 검토한다.**

| 시나리오 | 탐지 | 분류 | 통합 판단 |
|---|---|---|---|
| A | YOLO11m | YOLO11m | 규칙 기반 |
| B | YOLO11m | CNN | 규칙 기반 |
| C | YOLO11m | SVM | 규칙 기반 |
| D | YOLO11m | Random Forest | 규칙 기반 |

### 시나리오 A — YOLO 단독

- YOLO가 안경 탐지와 분류를 동시에 수행
- 현재 바운딩 박스 라벨링을 그대로 활용
- 별도 분류 모델 학습이 필요 없음
- 구현 난이도가 가장 낮음

### 시나리오 B — YOLO + CNN

- YOLO로 안경 위치 탐지
- 탐지된 안경 이미지를 잘라 CNN으로 분류
- 이미지의 외형적 특징을 학습
- 별도 CNN 학습 필요

### 시나리오 C — YOLO + SVM

- YOLO로 안경 위치 탐지
- 탐지된 이미지에서 특징 추출
- 추출된 특징으로 SVM 분류
- 별도 특징 추출 및 분류기 학습 필요

### 시나리오 D — YOLO + Random Forest

- YOLO로 안경 위치 탐지
- 탐지된 이미지에서 특징 추출
- 추출된 특징으로 Random Forest 분류
- 별도 특징 추출 및 분류기 학습 필요

※ B~D는 기존 개별 이미지 및 라벨을 활용할 수 있지만, 분류용 데이터 가공과 추가 학습이 필요하다.

※ 모든 시나리오는 비교 후보이며, 현재 최종 분류 방식은 확정되지 않았다.

## 5. 정면·측면 통합 판단

정면과 측면 사진을 각각 분석한 후, 두 결과를 결합하여 하나의 최종 판정을 출력한다.

현재 학습 데이터에는 동일한 안경의 정면·측면 사진 쌍이 충분하지 않으므로, 쌍으로 학습하는 별도 멀티뷰 분류 모델은 우선 제외한다.

대신 **두 사진의 분류 점수와 카메라 렌즈 탐지 정보를 결합하는 규칙 기반 판단 방식**을 검토한다.

### 통합 방법 후보

| 방법 | 설명 |
|---|---|
| Average | 정면·측면 점수의 평균 사용 |
| Max | 두 사진 중 높은 점수 사용 |
| Weighted Average | 정면과 측면에 서로 다른 가중치 적용 |
| 조건 기반 | 렌즈 발견 여부 등 추가 조건을 함께 반영 |

※ 통합 방식은 아직 미정이다.

※ 예측 신뢰도는 실제 AI 안경일 확률과 동일하지 않으며, 분류 모델에 따라 점수 산출 방식도 달라질 수 있다.

## 6. 최종 판정 기준

### 출력 결과

- **AI 안경 의심:** AI 안경 또는 카메라 렌즈의 증거가 충분한 경우
- **일반 안경 추정:** 일반 안경으로 판단할 근거가 충분한 경우
- **확인 필요:** 정보 부족 또는 판정 불확실성이 존재하는 경우

### 추후 결정 사항

- 분류 결과를 통합하는 방법
- 카메라 렌즈 탐지 결과의 반영 비중
- AI 안경 의심 판정 임계값
- 일반 안경 추정 판정 기준
- 정면·측면 결과 불일치 처리 기준

임계값은 실제 실험을 통해 결정한다.

※ 이미지 업로드 테스트는 실제 카메라 촬영 조건까지 검증하는 것은 아니다.

※ 테스트용 자료는 학습 데이터와 분리하고, 외부 이미지 및 영상의 사용 권한을 확인한다.

## 12. 구현 (시나리오 A: YOLO11m 탐지 + YOLO11m-cls 분류) — `code/yolo/`

| 파일 | 역할 |
|---|---|
| `config.py` | 경로, 클래스, 최종 판정 임계값(≥0.8 AI 안경 / ≤0.5 AI 안경 아님 / 그 사이 AI 안경 의심) |
| `prepare_data.py` | 중복 제거본 생성(`work/det_data`), train+val을 **그룹·층화 5-fold**로 분할(동일/유사 사진은 같은 fold), fold별 yaml·분류 크롭 생성 |
| `train.py` | 하이퍼파라미터 후보마다 **5-fold 교차검증** (탐지: mAP 기반 fitness, 분류: top-1 평균±표준편차) → 최적 후보로 train+val 전체 최종 학습 → `models/` 저장 |
| `pipeline.py` | 탐지 → 분류 → 렌즈 반영 → 정면·측면 통합 → 최종 판정 |
| `optimize_decision.py` | fold 모델의 **out-of-fold 예측**(train+val 전체 약 347장)으로 통합 판단 파라미터(det_conf, w_cls, 렌즈 비중, 통합 방식) 격자 탐색 |
| `evaluate.py` | test 데이터로 탐지/분류/최종 시스템 평가 (F1, 미탐률, 오탐률, Confusion Matrix) |
| `predict.py` | CLI: `py -3.12 predict.py 정면.jpg 측면.jpg` |
| `app.py` | Streamlit GUI (이미지 업로드 / 카메라 촬영, 정면·측면 2장) |

**실행 순서**

```
cd code/yolo
py -3.12 -m pip install -r requirements.txt
py -3.12 prepare_data.py
py -3.12 train.py                 # 5-fold 탐색 + 최종 학습 (탐지 → 분류, 약 2~3시간)
py -3.12 optimize_decision.py
py -3.12 evaluate.py test
py -3.12 -m streamlit run app.py
```

### 12.1 다른 PC(집)에서 학습하기

1. **코드·데이터 받기** — 데이터셋(`labeldFiled`)도 저장소에 포함되어 있다.
   ```
   git clone https://github.com/minkukwon/Team03Midterm.git
   cd Team03Midterm
   git checkout feat/KMK-code
   ```
   (이미 clone 했다면 `git fetch` 후 `git checkout feat/KMK-code` → `git pull`)
2. **환경 설치** — NVIDIA 드라이버가 설치된 PC, Python 3.10~3.12
   ```
   pip install torch torchvision --index-url https://download.pytorch.org/whl/cu124
   pip install -r code/yolo/requirements.txt
   python -c "import torch; print(torch.cuda.is_available())"   # True 여야 함
   ```
   Windows에서 여러 Python이 있으면 `python` 대신 `py -3.12` 사용.
3. **경로 수정 불필요** — 모든 경로는 `config.py`가 저장소 위치 기준으로 계산한다.
4. **실행** (`code/yolo` 폴더에서, 순서대로)
   ```
   python prepare_data.py          # 1분 내외
   python train.py                 # RTX 3060 기준 약 2~3시간
   python optimize_decision.py     # 1~2분
   python evaluate.py test
   ```
   - 중간에 끊기면: 탐지가 끝났으면 `python train.py --stage cls`,
     탐색까지 끝났으면 `--skip-search` 로 최종 학습만 다시 실행.
   - 시간 단축: `python train.py --trials 2 --search-epochs 20`
   - GPU 메모리 부족(OOM) 시: `train.py`의 `run()`에서 `batch` 값(16/8)을 절반으로.
5. **결과물** — `code/yolo/models/` 폴더 전체
   (`det_best.pt`, `cls_best.pt`, `*_best_hparams.json`, `decision_params.json`, `folds/`)
   GUI를 실행할 PC의 같은 위치에 복사하면 된다. `models/`는 `.gitignore`로 제외되어 있으므로
   USB/클라우드로 옮긴다 (GUI에는 `folds/` 불필요).
6. **GUI 실행:** `python -m streamlit run app.py`

**이미지 1장 점수:** `p = w_cls·P_cls(AI) + (1-w_cls)·(0.5 + 0.5·(conf_AI − conf_Normal))`,
렌즈 탐지 시 `p ← p + (1-p)·lens_weight·conf_lens`. 안경·렌즈 모두 미탐지 시 재촬영 요청.

**정면·측면 통합:** mean / max / weighted / cond(렌즈가 확인되면 max, 아니면 가중평균) 중 val 최적값 사용.
동일 안경의 정면·측면 쌍 데이터가 없으므로, 같은 클래스의 이미지 2장을 묶은 모의 쌍으로 최적화한다.

**데이터 주의:** 원본 val 77장 중 46장이 train과 동일한 파일이었다. 이 46장은 train에서 제외했다(원본 `labeldFiled`는 수정하지 않음).
5-fold 분할 시 dHash로 찾은 유사 사진도 같은 fold로 묶어 누수를 막는다. test 12장은 fold에 넣지 않고 최종 평가에만 쓴다.
