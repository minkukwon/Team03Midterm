# AI 안경 탐지 시스템

## 1. 프로젝트 개요

시험 응시자가 착용한 안경에 카메라가 장착되어 있는지 판별하는 AI 기반 시스템을 개발한다.

응시자의 정면(필수) 및 측면(선택) 사진을 입력받아 안경과 카메라 렌즈를 탐지하고, 두 사진의 분석 결과를 종합하여 AI 안경 착용 의심 여부를 판단한다.

실시간 카메라 촬영과 이미지 업로드를 모두 지원하는 웹 GUI(Streamlit)로 구현하였다.


## 2. 전체 시스템 구조

**사진 입력 → 탐지 → 분류 → 정면·측면 통합 판단 → 결과 출력**

1. **입력:** 동일한 응시자의 정면 사진 1장(필수) + 측면 사진 1장(선택)
2. **탐지(Detection):** YOLO11m으로 안경(`AIGlasses` / `NormalGlasses`)과 카메라 렌즈(`AIGlasses_Lens`) 탐지
3. **분류(Classification):** YOLO11m의 클래스 점수로 일반 안경과 AI 안경 구분 (시나리오 A, 최종 채택)
4. **통합 판단(Decision):** 렌즈 탐지 여부를 우선 반영하는 조건 기반 3단계 규칙
5. **결과 출력:** 바운딩 박스, 사진별 점수, 최종 판정(AI 안경 의심 / 확인 필요 / 일반 안경 추정)


## 3. 데이터셋 구축 및 학습

### 3.1 데이터셋 구성

- 인터넷에서 수집한 일반 안경 및 카메라 장착 AI 안경 이미지 활용
- 정면, 측면, 45도 등 다양한 각도의 개별 이미지 사용
- 동일한 안경의 정면·측면 사진 쌍은 학습에 필수적이지 않음 (최종 평가에만 사용)
- 현재 팀원들이 진행하는 바운딩 박스 라벨링 방식 유지
- 학습·검증·테스트 데이터의 중복 방지 (`prepare_dataset.py`로 자동 처리)

### 3.2 라벨링 클래스

| 클래스 번호 | 클래스 이름 | 설명 |
|---|---|---|
| 0 | `AIGlasses` | AI 안경 전체 |
| 1 | `AIGlasses_Lens` | AI 안경의 카메라 렌즈 |
| 2 | `NormalGlasses` | 일반 안경 전체 |

**라벨링 방식**

- 일반 안경: `NormalGlasses` 바운딩 박스
- AI 안경: `AIGlasses` 바운딩 박스
- 카메라 렌즈가 보이는 AI 안경: `AIGlasses`와 `AIGlasses_Lens` 바운딩 박스
- 카메라 렌즈가 보이지 않는 AI 안경: `AIGlasses` 바운딩 박스만 사용

※ 원본 `labeldFiled/labels`에 남아 있는 클래스 3(`NoGlasses`) 라벨은 학습용 정리 과정에서 제외한다.

### 3.3 데이터 정리 (`prepare_dataset.py`)

원본 `labeldFiled`는 수정하지 않고, 정리된 사본을 별도 폴더에 만들어 학습에 사용한다.

| 문제 | 처리 |
|---|---|
| 같은 사진이 jpg·png로 중복 저장됨 | 하나만 남김 (png·박스가 많은 쪽 우선) |
| 같은 사진이 train과 val에 동시에 존재 (데이터 누수) | 하나만 남김 |
| 같은 제품의 비슷한 사진이 train·val에 나뉨 | 이미지 해시(dHash)로 그룹화 → 그룹 단위로 분할 |
| 클래스 3(`NoGlasses`) 라벨 잔존 | 제거 (3개 클래스만 사용) |

- 분할: 그룹 단위, AI/일반 비율 유지, train : val = 80 : 20, seed 42
- 결과: train+val 393장 → 중복 제거 후 313장 (train 249 / val 64), test 12장은 그대로 사용
- train·val·test 간 중복 사진 0건 확인

### 3.4 데이터셋 설정

`prepare_dataset.py`가 정리된 폴더에 `data.yaml`을 새로 만든다.

```yaml
path: <정리된 데이터셋 폴더>
train: images/train
val: images/val
test: images/test

names:
  0: AIGlasses
  1: AIGlasses_Lens
  2: NormalGlasses
```

※ `path`는 실행한 컴퓨터의 경로로 자동 기록된다. `path` 줄을 지우면 Ultralytics가 `data.yaml`이 있는 폴더를 기준으로 경로를 찾는다.

### 3.5 학습 설정 (`yolo/train_yolo11m.py`, `cv_pipeline.py`)

| 항목 | 설정 |
|---|---|
| 객체 탐지 모델 | YOLO11m (COCO 사전학습 `yolo11m.pt`에서 시작) |
| 학습 횟수 | 최대 100 epochs |
| 조기 종료 | 검증 성능이 30 epochs 동안 개선되지 않으면 종료 (교차검증 fold는 25) |
| 이미지 크기 | 640 |
| 배치 크기 | 16 (GPU 메모리에 맞게 조정) |
| 학습률 스케줄 | Cosine LR |
| 기타 | 마지막 10 epochs mosaic 끔, AMP, RAM 캐시, seed 42 고정 |

## 4. 모델 구성 시나리오

YOLO11m 사용은 확정이며, 분류 방식으로 A(YOLO 단독)와 D(YOLO + Random Forest)를 실험으로 비교하였다.

| 시나리오 | 탐지 | 분류 | 통합 판단 | 상태 |
|---|---|---|---|---|
| A | YOLO11m | YOLO11m | 규칙 기반 | **최종 채택** |
| B | YOLO11m | CNN | 규칙 기반 | 미실험 |
| C | YOLO11m | SVM | 규칙 기반 | 미실험 |
| D | YOLO11m | Random Forest | 규칙 기반 | 실험 완료, 미채택 |

### 시나리오 A — YOLO 단독 (채택)

- YOLO가 안경 탐지와 분류를 동시에 수행
- AI 안경 점수 = AI 신뢰도 / (AI 신뢰도 + 일반 안경 신뢰도)
- 렌즈 점수 = 안경 박스 주변에서 탐지된 `AIGlasses_Lens`의 최대 신뢰도

### 시나리오 D — YOLO + Random Forest (실험)

- YOLO로 가장 확실한 안경 박스를 찾아 잘라냄
- 특징: HOG(테 모양·윤곽) + HSV 색상 히스토그램 + 가로세로 비·엣지 밀도·어두운 픽셀 비율 + YOLO 점수·렌즈 점수 (2단계 분류기)
- Random Forest(트리 600개, class_weight=balanced)로 AI 안경 확률 계산
- 결과: 사진 1장 단위 AUC가 YOLO 단독(0.977)보다 낮아(0.960) 최종 판정에는 사용하지 않음. 판정에 결정적인 정보는 카메라 렌즈 탐지였고, RF가 추가로 주는 정보가 거의 없었다.

## 5. 정면·측면 통합 판단

정면과 측면 사진을 각각 분석한 후, 두 결과를 결합하여 하나의 최종 판정을 출력한다.

학습 데이터에는 동일한 안경의 정면·측면 사진 쌍이 충분하지 않으므로, 쌍으로 학습하는 멀티뷰 모델 대신 **두 사진의 점수와 카메라 렌즈 탐지 정보를 결합하는 규칙 기반 방식**을 사용한다.

### 5.1 통합 방법 비교 방법 (`cv_pipeline.py`)

검증 데이터는 YOLO가 best 모델을 고르는 데 이미 쓰이므로, 통합 방식 선택에는 **5-fold 교차검증**을 사용하였다.

1. train+val 313장을 비슷한 사진 그룹 단위로 5등분 (AI/일반 비율 유지)
2. fold마다 YOLO11m을 새로 학습하고, 학습에 쓰지 않은 사진에서 점수를 계산 → 313장 전체에 대해 "처음 보는 사진" 점수 확보
3. 같은 클래스 안에서 가로로 넓은 박스(정면형)와 좁은 박스(측면형) 사진을 짝지어 유사 쌍 1,200개 생성
4. 시나리오(A, D) × 통합 방법 4가지 × 파라미터 × 임계값을 모두 비교

### 5.2 통합 방법별 결과 (교차검증 쌍 1,200개, balanced accuracy)

| 방법 | 설명 | A: YOLO 단독 | D: YOLO + RF |
|---|---|---|---|
| Average | 정면·측면 점수의 평균 | 0.975 | 0.966 |
| Max | 두 사진 중 높은 점수 | 0.935 | 0.952 |
| Weighted Average | 정면 w, 측면 1−w 가중치 | 0.975 (w=0.5) | 0.977 (w=0.7) |
| 조건 기반 | 렌즈 신뢰도 ≥ 0.55이면 AI 의심, 아니면 평균 | **0.992** | 0.990 |

→ **시나리오 A + 조건 기반**이 가장 좋았다.

### 5.3 최종 판정 규칙: 조건 기반 3단계

2단계(AI/일반) 조건 기반 판정은 두꺼운 검은 뿔테 일반 안경을 AI 안경으로 오판하는 문제가 있어, README의 세 가지 출력에 맞춘 3단계 규칙으로 확장하였다.

| 조건 | 판정 |
|---|---|
| 정면·측면 중 하나라도 **렌즈 신뢰도 ≥ 0.55** | 🚨 **AI 안경 의심** |
| 렌즈는 없지만 **AI 안경 점수(평균) ≥ 0.7** | ⚠️ **확인 필요** (모양은 AI 안경과 비슷함) |
| 그 외 | ✅ **일반 안경 추정** |
| 사진에서 안경 탐지 실패 | 재촬영 요청 |

- 측면 사진이 없거나 한쪽에서만 안경이 탐지되면, 탐지된 사진만으로 같은 규칙을 적용한다.
- 판정 기준은 `models/best_config.json`에 저장되며, 웹 GUI에서 조정할 수 있다.

※ 예측 신뢰도는 실제 AI 안경일 확률과 동일하지 않다.

## 6. 최종 판정 기준

### 출력 결과

- **AI 안경 의심:** 카메라 렌즈가 탐지된 경우 (렌즈 신뢰도 ≥ 0.55)
- **확인 필요:** 렌즈는 보이지 않지만 안경 모양이 AI 안경과 비슷한 경우 (AI 안경 점수 ≥ 0.7)
- **일반 안경 추정:** 렌즈와 AI 안경 특징이 모두 충분하지 않은 경우

### 결정된 기준

| 항목 | 값 |
|---|---|
| 분류 결과 통합 방법 | 조건 기반 3단계 |
| 카메라 렌즈 판정 기준 | 0.55 (렌즈 탐지가 최우선) |
| AI 안경 모양 기준 (확인 필요) | 0.7 |
| 정면·측면 결과 불일치 | 어느 한쪽이라도 렌즈가 보이면 AI 의심, 아니면 두 사진 점수 평균 사용 |

## 7. 탐지 신뢰도 및 예외 처리

### 탐지 신뢰도

- YOLO 안경 탐지 신뢰도 기준: `0.25` (이보다 낮으면 "안경 탐지 실패")
- 렌즈·클래스 점수 계산에는 0.05 이상의 낮은 신뢰도 탐지까지 함께 사용
- 최종 판정 기준(0.55 / 0.7)과 YOLO 탐지 신뢰도 기준(0.25)은 구분하여 설정

### 예외 처리

| 상황 | 처리 방법 |
|---|---|
| 안경 탐지 실패 | 재촬영 또는 이미지 재입력 요청 |
| 사진이 흐리거나 안경이 가려짐 | 재촬영 요청 |
| 측면 사진 미입력 | 정면 사진만으로 판정하고, 측면 사진 추가를 안내 |
| 한쪽 사진에서만 안경 탐지 | 탐지된 사진만으로 판정 |
| 정면·측면 결과 불일치 | 통합 판단 기준 적용 |
| 렌즈 없이 AI 안경과 비슷한 모양 | 확인 필요 |
| 재촬영 후에도 판정 불가 | 관리자 직접 확인 |

※ 카메라 렌즈가 보이지 않거나 탐지되지 않았다는 이유만으로 일반 안경이라고 확정하지 않는다.

## 8. GUI 및 실행 환경

### 8.1 개발 방향

GUI와 실시간 카메라 연동은 교수님의 필수 요구사항이 아니라 **팀 자체 개발 목표**이다.

GUI는 파이썬 기반 **Streamlit 웹 앱**(`app.py`)으로 구현하였다.

### 8.2 주요 기능

1. 입력 방식 선택: 이미지 업로드 / 카메라 촬영
2. 정면 사진 1장 입력 (필수)
3. 측면 사진 1장 입력 (선택)
4. 분석 실행
5. 탐지된 안경·렌즈 바운딩 박스 표시 (AI 안경 빨강, 렌즈 노랑, 일반 안경 초록)
6. 사진별 AI 안경 점수, 렌즈 신뢰도, 안경 탐지 신뢰도 표시
7. 정면·측면 결과 통합 및 최종 판정 출력
8. 탐지 실패 시 재촬영 안내
9. 사이드바에서 YOLO 탐지 신뢰도, 렌즈 판정 기준, AI 모양 기준 조정

### 8.3 코드 구성

| 파일 | 역할 |
|---|---|
| `prepare_dataset.py` | 원본 데이터 정리 (중복·누수 제거, 그룹 단위 재분할, 클래스 3 제거) |
| `yolo/train_yolo11m.py` | YOLO11m 단일 학습 |

| `test_pairs.csv` | test 정면·측면 쌍 목록 (`front,side,label`) |

브라우저에서 `http://localhost:8080` 접속.

- 포트와 실행 옵션은 `code/.streamlit/config.toml`에 설정되어 있다 (포트 8080, 이메일 입력 안내 생략).
- Streamlit 기본 포트(8501)는 Windows(Hyper-V·WSL·Docker)가 예약해 막는 경우가 있어 8080을 사용한다. `PermissionError: [WinError 10013]` 또는 `Port ... is not available` 에러가 나면 `streamlit run app.py --server.port 9000`처럼 다른 포트로 실행한다. 예약된 포트 범위는 `netsh interface ipv4 show excludedportrange protocol=tcp`로 확인할 수 있다.

**다시 학습하는 경우** (`code` 폴더에서)

```bash
python prepare_dataset.py --src ../labeldFiled --dst <정리된 데이터셋 폴더>
```

```bash
python cv_pipeline.py --data <정리된 데이터셋 폴더> --work <작업 폴더> --models models
```

※ 학습에는 GPU가 필요하지만, 웹 GUI 실행(판정)은 CPU만으로도 가능하다.

※ 다른 기기에서 `http://192.168...` 주소로 접속하면 브라우저 보안 정책 때문에 카메라 촬영이 막힐 수 있으므로, 시연은 실행한 컴퓨터에서 `localhost`로 접속한다.

| 평가 데이터 | AI → AI 의심 | AI → 일반 (미탐) | 일반 → AI 의심 (오탐) | 일반 → 일반 | 확인 필요 |
|---|---|---|---|---|---|

**테스트 자료 확보 방법**

- 일반 안경: 팀원 직접 촬영 또는 안경 착용 리뷰(try-on) 영상 캡처
- AI 안경: 실제 제품 착용 사진 또는 리뷰 영상에서 정면·측면 이미지 쌍 확보
- 카메라 촬영 기능과 이미지 업로드 기능 테스트

※ 테스트용 자료는 학습 데이터와 분리하고, 외부 이미지 및 영상의 사용 권한을 확인한다. 유튜브 캡처 등 저작권이 있는 이미지는 공개 저장소에 올리지 않는다.

### 9.4 한계

- 두꺼운 검은 뿔테 일반 안경은 YOLO가 AI 안경과 잘 구분하지 못해, "일반 안경 추정"까지 가지 못하고 "확인 필요"로 판정된다. 학습 데이터의 일반 안경(81장)이 AI 안경(199장)보다 적고, 뿔테 일반 안경 사진이 부족한 것이 원인이다.
- 정면 사진만 넣으면 안경 옆쪽 카메라를 확인하기 어려워, AI 안경을 "AI 안경 의심"으로 잡는 비율이 약 91%에서 69%로 낮아진다. 대부분은 "확인 필요"로 넘어간다.
- test 쌍이 6개뿐이라 test 결과는 참고용이다.
